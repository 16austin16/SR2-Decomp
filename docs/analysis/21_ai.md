# 21: AI (orientation)

This is a map of where the AI lives and what drives it. The AI code has almost no strings, so most of it is still unnamed. Names are in `docs/functions.csv` (subsystem `ai`).

## Entry points in the frame

From `sim_frame` (11_frame.md, 15_humans.md, 16_vehicles.md):

| Where | Function | What |
|---|---|---|
| sim_frame:1c | `humans_ai_update` (0x9A71B0) | for each human in the **AI list** `0x217043C` (+0x1294 link): `human_ai_pre_think` (0x9A9010), then **`human_ai_think`** (0x9C1B90). Then 0x9CF8F0 for each entry of the group list `0x215FFC0` (+0x1160 link: squads / followers) |
| sim_frame:1c | `humans_update_neighborhoods` (0x9A7080) | per-human neighborhood (`0x2526C94`, 0xA8-byte records from `neighborhoods.xtbl`), then 0x9CFB30, `followers_update` (0x98F680, "abandon followers"), 0x98DCC0, 0x986060 |
| sim_frame:4 | `humans_movement_update` (0x9A9890) | moves AI humans along their animation-driven path |
| sim_frame:5 | `vehicles_update` → **`vehicle_ai_drive`** (0xB2DD90) | AI driving for every vehicle; lightweight traffic only takes this path |
| sim_frame:5 | `population_update` (0x95A3D0, list `0x215E5C0`) | spawning and despawning of ambient population |
| sim_frame:6,7 | `notoriety_update` (0x55F1D0) | notoriety levels and the police / gang response (`xtbl_load_notoriety`, `xtbl_load_notoriety_levels`) |
| sim_frame:5 | `vehicles_cull_light` (0xAE1CF0) | keeps the lightweight traffic count at 4 or fewer |

`human_ai_think` (5 KB, no strings) checks the human's state (+0x46C, +0x10C8, +0x595), combat targets (0x971DE0 / 0x971E10, `0x974060` damage reactions), weapons (0x9707C0, 0x9C3D40) and vehicles (0xAE28F0, 0x9C6060). It shoots through `weapon_fire` and raycasts with 0x6FA330 for line of sight. The per-behaviour code is in 0x9B…-0x9C….

## Per-human AI flags

Scripts set behaviour flags by name, for example "ai_force_flags" + `always_run`, `cant_flee`, `deaf`, `driver`, `kamikaze`, `sidewalking`, `wandering` and so on. The force-flag bindings use the `human_ai_data` and `vehicle_ai` records (setters 0x43FDE0 … 0x440560 and 0xB2B8A0 … 0xB2C0E0). Vehicle AI uses "vai_force_flags".

## Paths

- **On foot**: Havok navmesh shapes (`havok_navmesh_shape`) built from chunk data. Pathfinding failures log "Vehicle navmesh pathfind failed." / "GPS pathfind failed" (debug strings, unreferenced in the shipping build). Multiplayer sends NPC spline paths as `npc_spline_pathfind_compressed / _uncompressed`.
- **Vehicles**: the road network: traffic lanes from `traffic_lanes.xtbl` and the chunks' road data, with `Road_Preference`, `Use_Roads` and `lane_type_preference`.

## Spawning and notoriety

- **Ambient population**: `population_update`, crowd density (`Pedestrian_Density`, Lua `set_ped_density` / `set_traffic_density`), spawn regions (`script_spawn_region`) and the distant impostor peds / traffic.
- **Notoriety response**: the spawn-group classes `notoriety_spawn_group` → `_police`, `_police_heli`, `_gang`, all from `special_vehicle_spawn_group`. Their slot names are still open in `docs/vtable_slots.csv`. Notoriety levels set how many response vehicles are wanted (`Notoriety_Vehicle_Count`, roadblocks with `Min/Max_Roadblock_Spawn_Time`).
