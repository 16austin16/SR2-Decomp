# 53: Game-side physics and world objects

Names are in `docs/candidates_physobj.csv` (136 new functions, notes end "(53)"); two corrections are in `docs/renames_physobj.csv`. Scope: the game wrappers around Havok (about 0x6F2000-0x720000), the object base, handles, items, props and movers (0x920000-0x960000, 0x9F0000-0xA00000). Not covered: the Havok library, AI, navigation, networking, vint, weapons, audio, effects, cameras, cutscenes, activities, weather.

Sources: 17_physics.md, 12_objects.md, 34_world_objects.md, 36_havok_map.md. The scripts used are in the scratchpad folder `physobj` (`scan.py` call-target scan, `cand.py` candidate lister, `summ.py` function summary, `fsize.py` real size and jump tables by control flow, `x87sym.py` symbolic x87 stack, `skel.py` callee / global / compare skeleton).

"Confirmed" in the CSV means the register convention, the data layout and the behaviour were read from the instructions. "Inferred" means the mechanics were read but the role (or a Havok class name) comes from context.

## 1. What the region holds

0x6F2000-0x720000 is not one subsystem. After the Havok memory classes (0x6F2D80-0x6F4000), RTTI collectors and the `game_havok_world` code, the unnamed functions are:

| Range | Content |
|---|---|
| 0x6F5700-0x6F5E70 | deferred world work: filter-update list, removal queue, add queue (section 2) |
| 0x6F8C60-0x6F9FD0 | `havok_world_create` helpers; two body pairs built from `havok_navmesh_shape` (globals 0x173A8C4/0x173A8C8 and 0x173A88C/0x173A890), each with a creator pair and a destroyer. Not named: the roles are unresolved |
| 0x6FA330-0x6FB040 | the cast layer (`physics_raycast`, `physics_linear_cast`, ground probes) |
| 0x6FC610-0x6FD800 | the body-table accessors (index into 0x28F25C0) |
| 0x6FE0E0-0x6FEF40 | AABB queries over the chunk list at 0xF70B88 (count 0xF6FBCC); callers are nav (`nav_closest_node_find`) and `trigger_objects_reap`. Not named |
| 0x6FF990-0x702700 | `physics_frame_time`'s neighbours: contact helpers, an STL `map` (0x700150-0x701410, "map/set<T> too long") |
| 0x702740-0x703600 | hkVector4 / hkTransform SSE helpers instantiated by the game build (the most-called functions of the region) |
| 0x703C40-0x70A730 | shape building (box tetrahedra and planes, shape-table collection), listeners; the label `hk_anti_gravity_action::vf7` (0x703C40) covers about 100 unnamed functions up to 0x70A730 |
| 0x70A730-0x70B880 | contact dispatch and the pair tables |
| 0x70C1F0-0x70D990 | constraint slot pool, constraint builders (ragdoll / limited hinge / hinge, breakable and malleable wrappers) |
| 0x710E20-0x719D50 | the ragdoll system |
| 0x71A8C0-0x71E4D0 | water simulation (render side; not mine) and Havok trigger cells |

The label problem: the earlier caller reports attribute call sites to the nearest named function above them. `physics_frame_time` (0x6FF860, really about 0x130 bytes) therefore appears as the "caller" of dozens of unrelated functions between 0x6FF990 and 0x702740. Treat caller names in older docs for this range with care.

## 2. Mechanisms found

### 2.1 Body table and rigid handles

- `0x28F25C0`: 0x18-byte entries, 5000 of them; +0 `hkpRigidBody *` (the body), motion at body+0xD0 (linear velocity at body+0x1A0, angular at body+0x1B0, centre of mass at body+0x130, transform at body+0xE0). Accessors: `physics_body_set_position` (motion vtable +0x30), `_set_rotation` (+0x34), `_set_transform` (+0x3C), `_set_linear_velocity` (+0x40), `_set_angular_velocity` (+0x44), `_apply_linear_impulse` (+0x48, existing name), `_apply_point_impulse` (+0x4C), `_apply_angular_impulse` (+0x50). All velocity and impulse setters wake the body first (0xD58FF0). The position / rotation / transform setters do nothing while `[0x2527DAC] > 0` (the world is stepping).
- `0x1693F60`: 0x157C (5500) rigid handle slots. A handle is `(seq << 16) | index`; the u16 sequence is `0xE8ECB4` (0 is skipped); free indices are the stack `0x168E970` with the used count in `0x2527DB0`. Every rigid body carries **property 8 = its handle**; `havok_rigid_handle_to_body` accepts a handle only when that property matches, so stale handles fail.
- Entity properties (16-byte entries at +0x74, count +0x78): 1 = owner object handle, 2 / 5 / 0xC = filter data set by `havok_entity_set_game_properties`, 8 = rigid handle, 0xE = material (index into the f32 table 0xDD1CA8; first entry 0.85).
- Motion type byte at body+0xD8: 6 (keyframed) and 7 (fixed) are not dynamic.

### 2.2 Deferred world work (while stepping)

Lock state `0x2527DC4` (0 free, 1 adding deferred, 2 stepping) and the step counter `0x2527DAC` gate every world change. The deferred lists are:

| List | Count | Use |
|---|---|---|
| `0x1699550` (u32 entities) | `0x2527DA8` | collision filter updates: `havok_collision_filter_update_defer` (add if absent, no capacity check), `_cancel` (zero), `havok_collision_filter_updates_flush` (`0xD5CC40(world, entity, 1)` each) |
| `0x168B738` (entities) | `0x2527DC0` | removals: `havok_removal_queue_push` flushes first at 2000 (0x7D0); `havok_removal_queue_flush` |
| `0x168E650` (pairs index, shape) | `0x2527DB4` | `havok_body_recreate` requests, replayed by `havok_add_queue_flush` after the step |

Filter value 0x8002E means "collide with nothing" (set by `havok_entity_collision_toggle` and by the ragdoll limb code); the pre-toggle value is kept by the caller.

### 2.3 Collision events

- Type-pair tables use the index `(hi + 1) * hi / 2 + lo` of the two object types (+0x4C). `0x1743D80`: 20-byte entries (phase 0 callback +4, phase 1 callback +8, contexts +0xC / +0x10); `0x1764D80`: 8-byte entries (filter callback + context); `0x1765140` / `0x17651B8` and `0x1765230` are the per-type handler tables. `physics_pair_tables_clear` (0x70B010) clears them; the registrations (0x709420, 717 bytes) fill them from about 30 pairs of globals (0x1743E00..0x1743F18, 0x17651C8..0x17652D4).
- Per-object contact lists: `0x175CD80` (4096 x 8 bytes, indexed by handle & 0xFFF) with a pool of 1000 nodes of 0x64 bytes (`physics_contact_lists_init`, `physics_contact_node_release`).
- `havok_game_filter_layers_collide` (0x70F8C0) is the layer matrix test: a 128 x 128 bitset at filter+0x34.

### 2.4 Constraints

A pool of 20-byte slots at `0x17695F0` (used ring `0x2527DF0`, free ring `0x2527DF4`, count `0x2527DEC`) and instance records on a ring `0x2527DFC` (count `0x2527DF8`). Builders read constraint definitions from a stream (`constraint_read_*_from_stream`, ECX = cursor pointer) or clone an existing definition (`constraint_clone_*`). Havok data classes seen: `hkpRagdollConstraintData` (0xD542A0), `hkpLimitedHingeConstraintData` (0xD54A00), `hkpHingeConstraintData` (0xD550E0), `hkpBreakableConstraintData` (0xD55730), `hkpMalleableConstraintData` (vtable 0xE53800).

### 2.5 Ragdolls

Pool of 12 records of 0x12A0 bytes from `0x2960F7C`; the first dword of record n at `0x2961060 + n * 0x12A0` is the owner object handle (0 = free). `ragdoll_find_for_object` (0x710DB0, Rust) returns the record. Layout seen: +0xE8C body count, +0xF70 owner handle, +0xF74 body pointer array, +0xF7C count, +0xFAC 8-byte entries per body (byte +0: bit 0 = no-collide toggled, bit 1 = dirty; +4 saved filter info), +0x1010 / +0x1018 constraint array and count, +0x1100 pending-impulse flag, +0x1108 in world, +0x1109 pending activation, +0x11AC..+0x11B4 last ground vec3, +0x11F4 four 0x34-byte limb entries, +0x1298 flags (bit 8 = skip one ground update). The pool size used is 11 or 12 slots (section 4, map G); slot 11 (0xB) is reserved for the local player.

### 2.6 Objects and handles

- The only shared handle lookup is `handle_to_object` (0x925030). The expression `[0x2149C64 + (h & 0xFFF) * 16]` plus the `obj+0x44 == h` test appears at about 4,300 places (byte matches of the table address in .text); over 200 small functions wrap it, and the commonly called ones are in the CSV (`handle_to_object_type3/4/5/6/7`, `handle_to_item_object`, `handle_to_general_mover`, `handle_to_player_human`, `handle_ptr_to_player_human`, `player_slot0/1_human_get`).
- The type test compiles to a branch-free mask: `setne cl; sub ecx,1; and eax,ecx` (returns the object only when the type matches) and, for the player test, `sub cl,1; neg cl; sbb ecx,ecx; not ecx; and eax,ecx` (object kept only when byte +0x3CC == 1).
- Items: the pool is the ring `0x215D790` (active, count `0x215D794`) with the free list head `0x215D784`; links are +0xB4 / +0xB8. Movers: the update rings headed by `0x21F2BF4` / `0x21F2BF8`, links +0x140 / +0x144, flag +0x198 bit 0.

## 4. Port maps

Ordering is by size. Sizes run from the first instruction to the final `ret` (`fsize.py`, control flow, not the padding). Read depth: A, B, C, F, I were read instruction by instruction; D, E, G were read in full but parts of the SSE / x87 lane order are marked as not traced; H and J were read for structure (H the first third, J only the generated skeleton of callees, globals and compares).

Conventions used below: "f32 store" is an `fstp dword` / `movss` store that rounds to single; x87 compares are given with a = ST0 (the value on top before the compare) and b = the operand. Masks: after `fcom*; fnstsw ax; test ah, M`: M=1 `jne` taken when a < b or unordered; M=5 `jp` taken when a >= b or unordered, `jnp` taken only when a < b; M=0x41 `jne` taken when a <= b or unordered, `je` only when a > b; M=0x44 `jnp` taken when a == b, `jp` when a != b or unordered.

### A. 0x6FA330 physics_raycast, 1257 bytes (ends 0x6FA818), cdecl with ECX = request

Frame: `push ebp; and esp,-16; sub esp,0x4d4`, cookie at +0x4d0, `ret` plain. Registers on entry: ECX = request R; stack arg 1 [ebp+8] = out header (its dword at +4 is cleared at the start and is the result count); arg 2 [ebp+0xC] = byte flag passed through to `0x6F5ED0`. The local hit arrays are hk-array-like {data, size, capacity|flags} and are freed only when the sign bit of their capacity word is clear. Returns AL = (out count != 0) (0x6FA788: `cmp [out+4], 0; setne bl`).

Request R (read offsets): +0 from vec3, +0xC to vec3 (read through `ebx = R+0xC`), +0x44 / +0x48 / +0x54 filter dwords, +0x4C kind, +0x50 mode, +0x54 filter pointer. Stack objects: from/to copies at +0x14..+0x2C, ray record at +0x44..+0x6C (flag byte +0x60 = 1, +0x68 = R+0x4C), all-hits collector (0x6F4DC0 ctor, ECX = stack +0x140), closest-hit collector with vtable 0xE189EC at +0x80, caster object with vtable 0xE1898C at +0xFC.

Sections:
1. 0x6FA336-0x6FA3CC: copy `from` and `to` into locals with `fld/fstp` (f32 copies). Thread block: `ecx = fs:[0x2c]; eax = [ecx]` then `[eax+0x6C] = R+0x54`, `[eax+0x64] = R+0x48`, `[eax+0x70] = R+0x44`. Two calls to `0xBF65F0` (EAX = point, ECX = 0x290FA8C, ESI = out, stack 0x290FA80) with `fstp st(0)` after each: clamps each end into the box 0x290FA80..0x290FA8C (both BSS vec3s set at world load). Result stored to the ray record.
2. Mode switch (0x6FA442): `eax = R+0x50 - 0`; `je` mode 0 -> block 4 (closest); `sub eax,1; jne 0x6FA6F4` anything but 1 skips casting (the output count stays 0 and the hit list is just freed).
3. Mode 1 (all hits, 0x6FA453): `0x6F4DC0` with ECX = collector (+0x140); `[esp+0x4cc] = R+0x54`; world = `[0x2527D94]`; `0xD7F660` with ECX = `[world+0x54]`, EDX = ray record, stack (collector, 0, `[world+0x70]`, caster at +0xFC with vtable 0xE1898C). Then the hit array (count at +0x154, 0x60-byte records) is copied into a fresh array (`[0xDB807C]` returns the heap, `0xD2B850(size = count*0x60, 0x17)`; movaps copies of 0x60 bytes) and the 12-byte companion array likewise; `0x6F4F20` destroys the collector. Branch `jle` on the signed count skips the copy when no hit.
4. Mode 0 (closest, 0x6FA5E0): ray record fields initialised to `fld1` (1.0 f32, hit fraction), -1 words, the closest collector built at +0x80 with vtable 0xE189EC; same `0xD7F660` call. When the collector's hit id (+0xD0) is non-zero: grow the record array by 0x60 (`0xD98D30(arr, 0x60)`), fill it with `0x701F90` (ECX = record, stack = collector) and set record +0x50 = hit id, grow the companion array by 12 and copy three dwords (position) from the collector.
5. Post-pass (0x6FA6F4): `edi = R+0x4C`; `cmp 0x52 -> sete dl`, `cmp 0x56 -> sete al` (kind 'R' and 'V' flags). For each record (stride 0x60, companion stride 12): scan the eight filter-id dwords at record+0x20 until -1 (`ecx` = last id, `eax` = count); then `0x6F5ED0` (callee pops 0x28 bytes) with ECX = record, EDX = 0, stack: out header, `[record+0x50]`, last id, flags, companion pointer, `fld [record+0x10]` (hit fraction, f32), and `[ebp+0xC]`.
6. Epilogue (0x6FA788): zero `[tls+0x6C]`, `[tls+0x64]`, `[tls+0x70]`; free the temp record array and companion array through `0xD2B7D0` unless the capacity word has its sign bit set (`js` / `test ..., 0x80000000; jne` skip); `mov al, bl`.

Globals: read 0x2527D94 (world), 0x290FA80 / 0x290FA8C (box), 0x31BF2BC / 0xDB807C (heap), fs:[0x2c] thread block. Constants: all literal values are the integers above; f32 1.0 via `fld1`, -1 words, 0x80000000 (sign flag marker in the array headers).
Polarity: no x87 compares in this function; the sign tests are on array capacities (`js`) and on counts (`jle` signed).
Port note: wrap `0xD7F660` (castRay) and `0x6F5ED0`; keep the thread-block writes and their reset.

### B. 0x6FA820 physics_linear_cast, 2073 bytes (ends 0x6FB038), cdecl with ECX = request

Entry: `mov eax,0x1d84; call 0xCA0820` (alloca probe), ECX = R in `edi`; arg 1 [ebp+8] = out header, arg 2 [ebp+0xC] = flag passed on to 0x6F5ED0, arg 3 [ebp+0x10] = byte (`cmp byte [ebp+0x10], al`: when 0 the second cast argument is the first collector at +0x220, otherwise 0). Returns AL = out count != 0; plain ret (three stack dwords popped by the caller).

Request (read offsets): +0 / +0xC from / to vec3, +0x18 radius f32, +0x1C optional shape owner object, +0x20 matrix (9 f32) used only with an owner, +0x44 / +0x48 / +0x54 filter dwords (same thread-block writes as A), +0x4C kind, +0x50 mode (0 closest, 1 all), +0x54 filter.

Sections:
1. Thread block: `[tls+0x64] = R+0x48`, `[tls+0x6C] = R+0x54`, `[tls+0x70] = R+0x44`; saved radius `fld [R+0x18]`.
2. Shape: if `R+0x1C != 0` call its vtable +0x1C (`this = owner`, stack: 0x31BF2D0, f32 0.0, &out at +0x100) to get two world points; the SSE length `sqrt(dx^2+dy^2+dz^2)` (shufps 0x55 / 0xAA, `addss`, `sqrtss`) is multiplied by f64 0.5 (0xE5BF70) giving the half length (f32 store to +0x2C). Otherwise the shape is a stack sphere (vtable 0xE54A44, refcount word 1, type 2) of radius R+0x18 and the half-length is the radius.
3. Bounds: the box vec3s 0x290FA80 (x,y,z, added) and 0x290FA8C.. (subtracted) combined with the half length; `0xBF65F0` called twice (ECX = out vec, EAX = point, ESI = out, stack 0x290FA80) as in A.
4. Orientation: with an owner (`R+0x1C != 0`) `0x70E280` (existing `mat44_from_mat33_pos`, ECX = R+0x20, EDX = out, stack R) else identity: `0x703480` (hkmatrix3 zero) then 1.0 at +0x170, +0x184, +0x198 (`fld1; fst`), `0x7034A0` zero of the translation then `movaps` of the start point. Then `0x7029E0` (ECX = start, EAX = out, stack (&xform, 0)).
5. Mode switch on R+0x50 as in A. Mode 1: two all-cast collectors (`0x6F50B0` at +0x220 and +0xFD0), `0xD5A630` (cast) with stack (xform, collector2, collector1 or 0 when `[ebp+0x10]` is non-zero, byte test `cmp [ebp+0x10], al`); results (0x30-byte records and 12-byte companions) copied the same way as A. Mode 0: collector with vtable 0xE18A04 (closest linear-cast), initial fraction f32 `[0xE5C288]` (0x7F7FFFEE, 3.4028200e38, not FLT_MAX), ids -1, `fldz`, same `0xD5A630`; a hit appends one record and one companion.
6. Post-pass: `cmp [R+0x4C], 0x52 / 0x56` flags and a per-record `0x6F5ED0` call with pushes (flag [ebp+0xC], companion pointer, 'V' flag, 'R' flag, ids, `fld [rec-0xc]` as f32 fraction, record pointers); callee pops 0x28.
7. Epilogue: `[tls+0x6C] = [tls+0x64] = [tls+0x70] = 0`; `bl = ([out+4] != 0)`; free both temporary arrays as in A (`0xD2B7D0(ptr, size*0x30 / *12, 0x17)` after `and size, 0x3FFFFFFF`, `js` skip).
Constants: 0xE5BF70 f64 0.5; 0xE5C1B0 f32 1.1920929e-07 (bits 0x34000000) loaded and stored twice into the cast input at +0xF0 / +0xF4; 0xE5C288 f32 bits 0x7F7FFFEE.
Polarity: only `jne`/`je` on pointers and counts (no x87 compare). Stack objects: sphere (0x50), caster (0x90), collectors (0x220, 0xFD0), arrays headers (0x14, 0x20).

### C. 0x7042B0 physics_box_to_mesh_lists, 2004 bytes (ends 0x704A83), cdecl with ECX = center, EDX = triangle list

Stack (after the 0x84 frame): arg 1 vertex list (u16 count at +0, vertices of 12 bytes from +4), arg 2 tetra list, arg 3 &rot (3 rows of 3 f32, 36 bytes), arg 4 &half (3 f32); ECX = &center. Plain `ret`.

Sections:
1. Scaled axes (x87, f32 store each): `u = row0 * hx` stored at +0x38 / +0x3C / +0x40, `v = row1 * hy` at +0x10 / +0x14 / +0x18, `w = row2 * hz` at +0x28 / +0x2C / +0x30 (each product stored as f32).
2. Eight corners, appended at `vertices + count*12 + 4` (base index = old count, kept in AX). Each is built left to right, f32-stored at every step (symbolic trace of the stack): v0 = ((c+u)+v)-w, v1 = ((c+u)+v)+w, v2 = ((c+u)-v)+w, v3 = ((c+u)-v)-w, v4 = ((c-u)+v)-w, v5 = ((c-u)+v)+w, v6 = ((c-u)-v)+w, v7 = ((c-u)-v)-w, written at offsets 0x00, 0x0C, 0x18, 0x24, 0x30, 0x3C, 0x48, 0x54. (The code reuses x87 stack slots holding u and v; a naive rewrite must keep the order of additions, e.g. v6 is (c-u)-v then +w.)
3. `add word [vertexlist], 8`.
4. Tetrahedra: skipped when arg 2 equals arg 1 (pointer compare `cmp edi, ecx; je`). Otherwise six entries of 4 u16 (8 bytes), appended at `list + count*8 + 2`, count u16 at +0 incremented per entry: with b = old vertex count the entries are (b+0, b+2, b+3, b+7), (b+0, b+2, b+6, b+7), (b+0, b+1, b+2, b+6), (b+0, b+1, b+5, b+6), (b+0, b+5, b+6, b+7), (b+0, b+4, b+5, b+7).
5. Triangles (EDX list): skipped when EDX == 0 after a tetra block, but when the tetra block was skipped the compare is against the vertex-list pointer instead (`cmp edx, ecx` with ECX = the vertex list in that path, 0 otherwise): quirk, keep it. A 36-word table is built on the stack; two passes of six triangles (entries of 3 u16, 6 bytes at `list + count*6 + 2`), each index + b: (0,1,2), (0,2,3), (1,5,6), (1,6,2), (5,4,7), (5,7,6), (4,0,3), (4,3,7), (0,4,5), (0,5,1), (3,7,6), (3,6,2).
Globals: none. Constants: none. Polarity: only the pointer compares above.

### D. 0x704A90 physics_shape_collect_mesh, 1636 bytes (ends 0x7050F4; jump table follows at 0x7050F4), cdecl, nine stack dwords

Stack: arg 1 [ebp+8] vertex list, arg 2 [ebp+0xC] saved to +0x3C, arg 3 [ebp+0x10], arg 4 [ebp+0x14] output point list (+0x4C), args 5-7 (0x18/0x1C/0x20) forwarded, arg 8 [ebp+0x24] = shape object (`ebx`), arg 9 [ebp+0x28] = transform (`esi`, vec3 at +0x30, orientation rows). Return ends with nine `ret` points.

Dispatch: `ecx = [shape+0xC] - 2; cmp ecx, 0xA; ja 0x7050DF` (unsigned; types outside 2..12 return); `jmp [ecx*4 + 0x7050F4]`. Decoded table: type 2 -> 0x704AE5, 3 -> 0x7050DF (exit), 4 -> exit, 5 -> 0x704B27, 6 -> 0x704C2B, 7 -> 0x704F02, 8 -> exit, 9 -> exit, 10 -> 0x705071, 11 -> exit, 12 -> 0x704B9F.
- Type 2 (point / sphere, 0x704AE5): only when arg 4 != 0: build a vec4 (transform vec3 +0x30..+0x38, w = `[shape+0x10]` radius) and call `0x7064C0` (EAX = list, EDX = vec4: appends 16 bytes unless count+1 > capacity, returns -1 then).
- Type 5 (box, 0x704B27): only when arg 1 != 0: `0x70DED0` converts the transform rotation (ECX = esi), extents from shape +0x20..+0x28 (f32 copies), calls `0x7042B0(ECX = center, EDX = [ebp+0xC])` with the rotation, then returns.
- Type 12 (0x704B9F): copy three vec4 from 0x31BF2D0 / 0x31BF2E0 / 0x31BF2F0 (identity transform) plus `[shape+0x20]` into a local transform, `0xD93C30`, recurse into `0x704A90` with the child at `[shape+0x18]` and 9 pushed args (cleaned with `add esp, 0x24`).

## 5. Port recipes (small functions)

Offsets are the unpacked exe's; every function here is a plain leaf or touches only the listed globals.

1. **handle_to_object (0x925030)**. Variants: add `obj+0x4C == k` (types 3,4,5,6,7 at 0xA009C0, 0x94DF70, 0xAA73C0, 0x50A890, 0xA6C810); type 2 via the mask form (0x931110); player human: type 1 and byte `obj+0x3CC == 1` (0x9D7DD0; the branch-free `sub cl,1; neg cl; sbb ecx,ecx; not ecx` keeps the object only when the byte is 1); general mover: type 3 and dword `obj+0xD0 == 3` (0x9FB770).

## 6. Surprises and open items

- The most-called functions of the region are not game logic: 0x7031C0 (149 callers), 0x7034A0 (106), 0x703480 (89), 0x702F40 (59), 0x702740 (48), 0x703580 (47) are Havok hkVector4 / hkTransform helpers that the compiler left out-of-line. A port of the game wrappers does not need them if Havok is replaced.
- `0x702F40` looks like `setAll(x)` but loads with `movss` so it stores `(x, 0, 0, 0)`; the true splat is `0x70EDB0`.
- The collision filter value 0x8002E (no collisions) is used by both the generic toggle and the ragdoll limb update; the original value is stored by the caller (entry +4 in the ragdoll record).
- The filter-update list `0x1699550` has no capacity test; the removal queue flushes itself at 2000 entries.
- `0x7042B0` skips the triangle list when `EDX` equals the vertex list pointer only on the "tetra skipped" path (`ecx` differs by path): an artefact of register reuse, but it is observable.
- The ragdoll pool has 12 records but only 11 are used unless `[0x2528B48] == 1 && [0x2528B49] == 0`; slot 11 is reserved for the local player in the other mode.
- `0x6FE0E0-0x6FEF40` (chunk AABB queries) and the four world-create body builders at `0x6F9100`, `0x6F9590`, `0x6F9A00`, `0x6F9CF0` were left unnamed; each needs a full read.
- Not done: the largest function of the area, `ragdoll_build_for_object` (0x711D40, 4993 bytes, 1152 instructions, 22 calls of 0xCE0C80 over bone tables), has no port map; it depends on the rig bone tables. Maps H and J are partial as marked.
